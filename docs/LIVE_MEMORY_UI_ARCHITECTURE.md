# Live Memory 界面与交互架构（2026-11）

本文是实现约束，不是纯视觉设计说明。现有 React/Vite/IndexedDB/Supabase 领域模型、数据格式和云同步接口保持稳定，视觉与交互层按可逐步替换的组件边界迭代。

## 一、基本原则

- **数据优先**：本机独立档案和个人云档案由现有账户作用域隔离；任何 UI 重做不改变记录 ID、媒体所有权、删除墓碑或同步冲突决策。
- **功能界面与分享图分离**：日常页面服务检索与编辑，Canvas 导出服务社交传播；两者同源但不强制共用 CSS、版式或私密字段。
- **任务先于字段**：编辑器围绕「演出信息 → 票务与同行 → 影像档案 → 现场回忆」组织，而不是把二十余个字段无差别排列。
- **稳定内容尺寸**：先改排版、分组和间距，不把字体压到 10px 以下去适配固定窗口；大屏、平板、手机均需要明确的滚动归属。
- **可回退材质**：Liquid Stage 是默认的高表现力玻璃视觉，Editorial 保留简洁阅读模式；低性能设备和减少透明度偏好可关闭昂贵的背景模糊。

## 二、代码边界

| 层级 | 当前文件 | 责任 |
|---|---|---|
| 材质与 tokens | `src/liquidStage.css` | 场景渐变、光感、玻璃变量、组件光学统一、响应式及降低动效/透明度策略 |
| 共享语义组件 | `src/ui/PagePrimitives.tsx` | 模块标题、空状态等一致的 DOM 语义，不承载业务数据 |
| 弹层行为 | `src/ui/useDialogBehavior.ts` | 多层弹窗焦点优先级、Escape、Tab 焦点约束、页面滚动锁、恢复焦点 |
| 编辑数据校验 | `src/ui/editorModel.ts` | 脏数据检测、演出日期与票价校验，不持有 UI 状态 |
| 编辑工作区 | `src/ui/editorWorkflow.css`、`src/overlays.tsx` | 四分区表单、图片处理提示、取消时二次确认、保存错误反馈 |
| 页面骨架与导航 | `src/experience.tsx` | 主路由/导航、主题选择、账户状态 |
| 档案、统计、分享 | `src/archive.tsx`、`src/statsPage.tsx`、`src/shareStudio.tsx`、`src/keepsakeStudio.tsx` | 各业务视图与可分享内容，按需逐步拆分模块 |

所有新弹层都应该接入 `useDialogBehavior`，避免另写不互通的 document.keydown、body overflow 或 ESC 监听；保存/识别进行中要禁用具有破坏性的关闭。

新模块优先使用材质/色彩 tokens 和 PagePrimitives。不再通过新建 `*Hotfix.css` 追加孤立的 override 来修复同一类问题。已有 CSS 属于逐步迁移范围，不应一次删除造成图件裁切与导出布局回归。

## 三、交互状态机与异常处理

1. 详情查看：打开 → 查看/图片放大/分享 → 返回原位置；图片放大时最上层弹窗获得键盘事件。
2. 编辑记录：原始快照 → 修改草稿 → 保存中或尝试关闭。保存前进行校验；保存失败保留当前草稿并显示可读错误；有修改时主动关闭先询问丢弃。
3. 批量导入：识别中不允许关闭，错误反馈在本弹窗内；已成功加入的单条草稿从待处理区移除，避免重复保存。直接上传海报会立即存入档案，需要明确告知。
4. 用户数据备份导入：JSON 先核验内容和增量，默认只添加未出现的记录 ID；在提交时从 IndexedDB 重读最新记录，避免覆盖编辑或同步结果。
5. 云同步：以当前账户 scope 作为异步操作边界；不在界面层绕过已有数据防护。

## 四、视觉与性能边界

- 海报、票根等内容应保持原长宽比。票根的封面与蒙版区域满版，不能为了模拟玻璃而强行给封面加内边距。
- 顶栏、主导航、二级抽屉和大型模块使用 `backdrop-filter`；海报墙等大量重复的元素使用层叠透明色/阴影而非每张卡片独立 30px 模糊，避免移动端 GPU 负担。
- 颜色不是装饰：重要按钮必须有清晰对比，警告和错误必须由文本说明，不能仅靠颜色或图标表示。
- `prefers-reduced-motion`、`prefers-reduced-transparency`、不支持 `backdrop-filter` 的浏览器需要等价的可读内容。
- 档案里所有记录和图片的身份由数据层确定；视觉刷新、主题切换不得重建档案、重发网络媒体请求或重置正在编辑的草稿。

## 五、验证与后续迁移

`npm run check` 应包含静态/领域模型校验、TypeScript 构建，`scripts/visual-audit.mjs` 应覆盖 1600px/390px 浏览器及详情、编辑、分享、导入、存储恢复。新增 UI 逻辑尽量用独立可执行回归，而不是仅断言 CSS 文本存在。

**当前属于统一架构第一阶段，不代表旧组件和 CSS 已全面拆完。** 后续优先：将 `shareStudio.tsx` 和 `archive.tsx` 的视图/数据控制拆开、提炼数据驱动的分享布局组件；清理重复样式、实现可选自托管/私有同步，再对 Web 与 Android 容器进行真实设备适配。每次以可运行版本、可回退 PR 和可截图核验为最小交付单位。
