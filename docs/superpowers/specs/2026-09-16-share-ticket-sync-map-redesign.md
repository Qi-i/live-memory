# Live Memory 分享、票根、画报、同步与地图重构设计

## 背景

当前 `main` 存在五类关联问题：

1. 分享图默认仍限制为 20 张，且缺少票根聚合视图；
2. 主页票根没有利用海报色彩形成统一的磨砂渐变视觉；
3. 主页“画报”使用固定 12 列 + 固定网格跨度，容易产生明显空洞和不均匀留白；
4. 云端恢复、远端更新检查和图片签名 URL 刷新虽有部分自动逻辑，但用户可见入口过深，且跨设备更新缺少显式状态和主动检查入口；
5. 地图 provider 设置与实际 `VenueView` 渲染未打通，导致切换高德后底图不变化。当前固定中国轮廓仅应作为离线兜底，不能继续作为默认地图体验。

## 目标

在不破坏现有档案数据结构和云同步兼容性的前提下：

- 分享图默认使用全部符合条件的记录；
- 新增票根聚合分享布局，并让主页票根与分享票根共享同一套磨砂渐变视觉语言；
- 将主页画报改成紧凑、自适应、低空洞率的视觉拼贴；
- 将云同步从“设置页功能”提升为全局可见、可主动触发、自动检查的应用能力；
- 真正接通高德地图 provider；已配置高德 Key 时优先渲染高德，缺少 Key 时明确提示配置，不再默认展示失真的固定中国轮廓。

## 非目标

- 不把个人高德 Key 或安全密钥硬编码、提交进公开仓库；
- 不引入新的持久化后端；
- 不重构现有 EventRecord schema；
- 不新增复杂地图编辑、轨迹规划或导航功能；
- 不在本轮实现百度地图的新功能扩展，但要保证 provider 不再出现“选择后无实际效果”的假状态。

## 1. 分享图

### 默认数量

`ShareStudio` 的 `itemLimit` 默认值改为 `"all"`。12 / 20 / 30 保留为用户主动限制选项。

### 新增票根聚合布局

`ShareLayout` 增加 `tickets`。该布局：

- 每个记录显示主海报缩略图、标题、艺人、日期、城市/场馆、座位、票价；
- 自动根据智能横版/智能竖版和记录数量计算列数、行数与票根尺寸；
- 预览和 PNG 导出使用同一套布局模型；
- 每张票根背景使用该记录海报作为低透明度模糊背景，同时叠加半透明玻璃层和 `record.colors` 渐变作为稳定兜底；
- 文本区域始终保证高对比度和可读性。

## 2. 主页票根视觉

`TicketView` 改为“海报色磨砂票根”：

- 卡片用记录海报生成绝对定位背景层，`cover + blur + scale`；
- 背景上叠加基于 `record.colors[0/1]` 的渐变遮罩；
- 正文区域使用半透明 surface + `backdrop-filter: blur(...)`；
- 保留票根锯齿/打孔视觉；
- 无海报时退化到 `record.colors` 渐变，不出现黑色空块。

分享图 `tickets` 布局与主页票根共享相同色彩和玻璃语义，但不强求复用同一个 React 组件，以避免 Canvas 导出依赖 DOM。

## 3. 主页画报

当前 `archive-showcase` 的固定 12 列、70px 行和 `index % 7` span 模式替换为紧凑 masonry 风格：

- CSS 使用多列/密集 masonry 近似方案或按记录宽高比计算 span 的密集 grid；
- 目标是显著减少 12 列固定 span 造成的大片空洞；
- 默认 gap 控制在 6–8px；
- 海报按自身比例展示，使用 `cover`，不制造额外白边；
- 标题信息采用底部渐变覆盖层；
- 保留点击打开与点击海报放大行为；
- 桌面、平板、手机按可用宽度自适应列数。

验收以浏览器实际布局为准：可见区域不得出现由布局算法造成、尺寸达到单张普通海报面积级别的空洞。

## 4. 云同步与新设备体验

### 现有行为保留

现有以下行为继续保留：

- 登录初始化执行 `syncAfterLogin()`；
- 本地变化触发 `autoSyncAll()`；
- 图片签名 URL 在启动、页面重新可见、恢复网络、图片加载错误及定时周期中自动刷新。

### 全局同步入口

顶部 `sync-pill` 从纯状态标签改为按钮/弹出面板入口。面板提供：

- `立即同步`：执行完整 `autoSyncAll()`；
- `检查其他设备更新`：强制拉取/合并远端记录；
- `刷新云端图片`：强制执行 `refreshSignedMediaUrls(..., { force: true })`；
- 显示最近同步时间、连接状态、图片同步是否开启和冲突数量。

### 自动远端检查

新增节流的远端主动检查：

- 登录完成后执行一次；
- `visibilitychange -> visible` 时，如果距离上次远端检查超过阈值则执行；
- `online` 时执行；
- 应用持续打开时按合理低频周期执行；
- 检测到其他设备的新记录/更新后合并到本地并用轻提示告知。

不得形成无限同步循环；远端检查后的本地落盘必须更新同步 fingerprint。

### 新设备提示

当已登录且云端连接有效，但本机记录为空或明显少于刚拉取的云端记录时，首页显示一次性“已从云端恢复 / 可刷新图片”的提示；不要求用户进入设置页。

设置页中的原“从云端恢复 / 刷新图片链接”保留为高级入口，但不再是唯一入口。

## 5. 高德地图

### 根因修复

必须将 `settings.map` 从 `ArchivePage` 继续传到 `ArchiveRenderer` / `VenueView`，并由 `VenueView` 根据 provider 真正切换实现。

### Provider 行为

- `amap`：有 `amapKey` 时加载高德 JS API 2.0，并渲染地图、城市/场馆 marker 和档案数量；如有安全密钥，必须在加载脚本前设置 `window._AMapSecurityConfig.securityJsCode`；
- `amap` 但缺 Key：不显示伪地图，显示醒目的“配置高德 Key”状态和直达设置入口；
- `baidu`：如果当前代码没有真实渲染实现，则在本轮明确显示“尚未接入”，而不是继续落到固定中国图；
- `none`：只保留轻量离线足迹摘要，不再用错误的中国行政轮廓作为默认主图；可以显示城市列表/统计式点阵作为无 API 退化视图。

### 默认选择

不修改用户现有 provider。对于新设置：如果未来存在安全的部署级公共 Key 机制，可以另行支持；本轮禁止将个人 Key 写入源码。

### 生命周期

高德脚本加载必须：

- 避免重复插入；
- 处理加载失败；
- 组件卸载时销毁 map 实例；
- provider/Key 变化时正确重新初始化。

## 6. 测试与验收

### 契约 / 单元测试

新增或扩展测试覆盖：

- 分享图默认 `itemLimit === "all"`；
- `ShareLayout` 包含 `tickets`；
- 票根聚合有独立 DOM/Canvas 绘制路径；
- 主页票根使用海报背景 + blur + 渐变；
- 画报不再使用旧固定 `index % 7` span 模式；
- AppController 暴露显式同步、远端检查、强制图片刷新动作；
- 高德 provider 的 settings 从 ArchivePage 贯通 VenueView；
- 缺 Key、高德可用、百度未接入三种状态明确区分。

### 浏览器视觉测试

Playwright 至少验证：

- 分享图打开后默认选择“全部”；
- 票根聚合在智能横/竖两种尺寸下无溢出，导出按钮可用；
- 主页票根可见磨砂背景，文本可读；
- 画报在 20+ 海报样本下无明显大洞；
- 顶部同步入口在桌面/手机均可访问；
- 高德 provider 缺 Key时显示配置提示；
- 测试注入可控 AMap stub 后，provider=amap 时实际创建地图容器和 marker，而不是继续渲染固定中国 SVG。
